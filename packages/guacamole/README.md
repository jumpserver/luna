# @jumpserver/guacamole

Private Luna workspace package. Browser and Electron renderer consumers import its default Guacamole namespace. There is no npm publication, install-time download, or dependency on a moving Git branch.

## Reproducible build

`dist/guacamole.js` is generated from these committed sources and the local module patches. The `dist/` directory is ignored by Git and is not committed. Do not edit the generated file directly.

- `source-manifest.json` pins the source order, SHA-256 and Git blob ID of each original source and license, and the local patch paths and target modules. Local patches are maintained in Git without manually recorded patch or generated-output hashes.
- `patches/Client.patch`, `Display.patch`, `SessionRecording.patch`, and `Tunnel.patch` contain the local changes against the corresponding original modules. `StaticHTTPTunnel` is part of `Tunnel.js`.
- `scripts/build.mjs` verifies the official inputs, applies the patches using exact positions and context, joins the modules in the recorded order, and appends the default ESM export. It calculates and reports the final runtime SHA-256 without writing it back to the manifest. It rejects missing/unlisted sources or patches, upstream checksum mismatches and stale patches, without fuzzy application.

Before patching, joining the original files with one LF separator reproduces the official unminified `all.js` digest above. Preserve each original file's exact bytes, including whether it ends with LF. Patches use standard unified-diff file headers, hunks and `\ No newline at end of file` markers; Git metadata, binary diffs, renames and multiple files per patch are not supported. Generate a new single-file unified diff when changing a patch instead of adjusting hunk counts manually.

Run these from the repository root:

```sh
node packages/guacamole/scripts/build.mjs
node packages/guacamole/scripts/build.mjs --check
node --test --test-concurrency=1 packages/guacamole/scripts/build.test.mjs
```

The equivalent workspace scripts are `pnpm --filter @jumpserver/guacamole build`, `build:check`, and `test:build`. `--check` validates the same official inputs and exact patch application, then compares the generated bytes with the local `dist/guacamole.js`. It fails if that output is missing or stale, without writing any files. Run a normal build first on a clean checkout. Normal generation leaves an already matching file untouched; changed output is written to a unique temporary file and atomically renamed so simultaneous startup builds cannot expose partial JavaScript.

The build needs only Node.js and its standard library: no Maven, Java, npm build dependency, Git/patch executable or network download. Nuxt setup generates the runtime for development, preparation and production builds for both Web and Electron renderers; the Vitest configuration also generates it before collecting tests. A direct consumer outside these entry points must run the package build first. Restart the entry point or run the package build after changing a patch. Client release CI exercises source-only build fixtures and Chromium regressions. Docker builds from the committed inputs instead of copying a host-generated runtime. The base image does not need a Java toolchain or a separately built Guacamole artifact.

## Local changes

Changes are marked with `JumpServer` comments and limited to the module export, `Client`, `Display`, `StaticHTTPTunnel`, and `SessionRecording`:

- Export the namespace as the default ES module export.
- Release decoded image bitmaps after drawing or cancellation, and unblock display frames when image decoding fails. Legacy Image rendering also clears image handlers and sources after drawing or cancellation, including cancellation of fallback Blob URLs.
- Release temporary snapshot canvases immediately after PNG encoding, without resizing or resetting the live layer. The exported state and snapshot restoration format remain unchanged.
- Preserve synchronous local `connect(data)`, closing the tunnel after parsing.
- Stream raw gzip or plain HTTP recordings, including split gzip signatures and UTF-8 characters. HTTP-decoded gzip is detected by its actual body. Report download/read/parser failures and stop cancelled requests without affecting replacement connections.
- Preserve `getPlaybackRate()` / `setPlaybackRate()`, remaining frame delays across pause/resume, and zero-based recording timestamps.
- Store tunnel recordings as independent frame Blobs, publishing each only after its complete bytes are available. This avoids rebuilding a growing prefix Blob at every sync; large frames retain 256 KiB buffering and trailing incomplete frames are released when the tunnel closes. Blob inputs retain their original storage. Count Blob offsets in UTF-8 bytes and protocol lengths in Unicode codepoints.
- Accept a seekable asynchronous `SessionRecording.Source` with `stream(signal)`, `read(start, end)` and `close()`. Index only frame timestamps and byte offsets; read individual frames when replayed. `dispose()` permanently cancels and releases source storage, reads, client timers and rendering work. Ordinary `abort()` preserves already indexed bytes for playback.
- Serialize asynchronous frame/snapshot work and cancel pending playback timers so speed changes and seeks cannot replay a frame twice. Wait for display/snapshot restoration before completing a seek.
- Discard the previous seek's playback-restoration state when paused. When playback explicitly interrupts a seek, complete its callback once without recursively restoring the previous playback state.
- During explicit seeks, snapshot only frame zero and the destination instead of PNG-encoding every crossed keyframe. Normal playback retains keyframe snapshots. Keep frame zero as the permanent backward-seek anchor and retain at most 32 other snapshots with a combined Blob size of 32 MiB, evicting the least recently used first. An individual non-anchor snapshot larger than 32 MiB is not retained. The anchor is separate from this budget and may itself exceed 32 MiB; the limit does not cover the recording, active canvases, or temporary encoding allocations. Evicted positions are reconstructed by replaying from an earlier retained state.

The original upstream files, generated runtime and declarations retain their source formatting and are excluded from repository formatting/lint rewrites. Repository attributes preserve LF line endings for this package across platforms.

## Recording storage

`@jumpserver/guacamole/recording-source` exports the typed `createRecordingSource()` factory used by both players. Plain local Files are sliced directly. Browser downloads, gzip Files and stored entry streams are streamed into a temporary IndexedDB database unique to each playback, without a full decoded string or retained per-frame payloads. `RecordingStreamInput` opens readable bytes directly, so an archived entry does not need to be assembled into a Blob first. Two historical gzip layers and HTTP-decoded bodies are supported. Each 2 MiB block is committed before it is exposed to the frame index; writes are serialized to apply backpressure. Reads use a 16 MiB LRU, independent of the snapshot budget. These limits exclude browser internals, the current frame/instruction and live canvases.

Electron's already-extracted `jms-asset:` files use validated HTTP 206 byte ranges and the same bounded read cache, without an IndexedDB copy. Native response headers expose Content-Range to the renderer. A source is owned by one recording and must be closed on unmount or failure; no recording cache is shared between accounts. Close deletes its temporary database, while a best-effort startup sweep deletes abandoned databases older than 24 hours where IndexedDB enumeration is available. An open database connection protects another active playback from deletion until it closes. Storage failure is reported without falling back to unbounded RAM. Private browser modes may back IndexedDB with memory and therefore do not promise the same memory savings.

Browser file import retains original Guacamole Files/Blobs and only inspects a short header. Browser tar imports stream entries into a separate temporary IndexedDB archive in 2 MiB blocks with serialized writes. The playlist retains entry indices and metadata, not payload Blobs. Inner gzip entries remain compressed in the archive; only the active Guacamole entry is streamed through the playback cache above. Switching parts deletes the old playback cache while retaining the shared archive. Removing its last playlist item, leaving the player, or aborting/failed import deletes the archive. Existing cast/MP4 players materialize only the selected entry, releasing it on switching. Electron archive import continues to stream to its existing disk storage without using the browser archive cache.

Archive imports validate tar checksums, lengths and gzip trailers and support USTAR, PAX and GNU long names. Indexes are limited to 10,000 ordinary files and 4096 characters per filename; extended tar metadata and each decoded recording JSON are limited to 1 MiB, with 16 MiB of decoded recording JSON per archive. Unsupported old GNU sparse archives fail explicitly. These limits bound metadata separately from payload chunks. Failed imports are removed instead of falling back to whole-archive memory storage.

## Updating

Updating the upstream snapshot is an explicit maintenance operation. Normal installs, development, builds and CI continue to use the committed inputs without downloading a newer release.

From the repository root:

```sh
pnpm guacamole:update 1.6.0 --dry-run
pnpm guacamole:update 1.6.0
```

The first command prepares an upstream-only candidate and `report.json` in a temporary directory, without changing this package or its existing `dist/`. The second replaces only `upstream/`, LICENSE, NOTICE, the source manifest's `upstream`/`sources`/`licenses` fields, and the README's upstream provenance section. Both accept an exact numeric release, not a moving branch or `latest`, and require Node.js, Git, installed workspace dependencies (reusing `fflate`), and network access to GitHub and Maven Central.

The updater resolves the release tag to a full commit, verifies the complete module set and each Git blob against the official ZIP, and reproduces official `all.js` byte-for-byte to determine assembly order. Downloads and decompressed files have size limits and requests have timeouts. SHA-256 values are recorded for the ZIP and upstream inputs. These checks establish source/artifact consistency; they do not perform a separate PGP signature verification.

Local patches are maintained independently. The command does not read, merge, apply, regenerate or validate them, and does not require them to be present or valid. It preserves patch metadata, the workspace package version, type declarations and `dist/` without running the builder. Uncommitted patch changes and unrelated manifest/README content are retained. A successful upstream update therefore does not imply that local patches apply or that the new runtime builds: those are separate maintenance steps below. This separation also allows the local patch implementation to evolve without coupling it to upstream downloads.

Applying an update requires clean upstream/license files. Inputs are rechecked before replacement, with rollback if a replacement fails. A sibling lock serializes publication. If a process is interrupted, inspect the sibling `.guacamole-upgrade-*` backup directory and lock before retrying; retain unfinished backups. Download/verification failures leave the current package untouched. The command never changes CI or Docker configuration, commits or pushes.

Run `pnpm --filter @jumpserver/guacamole test:upgrade` for the offline updater tests. After updating upstream, separately:

1. Adapt the local patches to the new original modules, resolve conflicts, and remove fixes now provided upstream. Review every retained local behavior above, especially asynchronous source/disposal, seek serialization, snapshot budgets and image cleanup. Regenerate diffs against the untouched upstream files; never replace the runtime with an unpatched upstream bundle.
2. Update the patch paths and target modules in `source-manifest.json` only when adding, removing or retargeting patches. Run the build to validate exact patch application and regenerate the runtime; its digest is calculated automatically and requires no manifest update. Review the patch and builder changes, then update the workspace package version and local-change notes when integration is complete.
3. Reconcile internal declarations with the new APIs and retained extensions. A matching `@types/guacamole-common-js` version alone is insufficient. Run `build`, `build:check`, `test:build`, and strict package typechecks in both configured module-resolution modes.
4. Run the tunnel, display and recording tests in Node and Chromium, plus replay end-to-end tests. Validate play/pause, playback rate, forward/backward seek, cancellation, error handling, import and cleanup with real recordings on Web and Electron. Verify live connections and both production builds, then commit the reviewed integration together. Leave `dist/` untracked.

For a local fix within the same upstream release, leave `upstream/` unchanged: regenerate the affected patch, run the package build and relevant tests, and review the patch diff. No manifest hash update or `guacamole:update` command is needed. The computed runtime digest identifies output bytes; it does not replace code review or connection/playback tests.
