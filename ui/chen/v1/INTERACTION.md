# Chen 数据库工作区交互规格

状态：**首批交互已实现，完整规格分阶段交付。** 日期：2026-10-23。

本文用于实现与验收 MySQL / PostgreSQL 工作区。首批已实现真实对象树（数据库、Schema、表 / 视图、列）、按需分页与服务端搜索、独立查询 / 结构页签、明确触发的数据预览、断线编辑及关闭保护。目录使用独立 HTTP 连接池，查询状态复用会话 SSE，不新增 WebSocket。

方言展示已扩展到 MariaDB、Oracle、SQL Server、Db2、Dameng、ClickHouse，以及 OceanBase 的 MySQL / Oracle 两种模式。新增库的名称引用、树层级、默认查询、预览限行、补全过滤与大字段类型通过单元 / 协议测试检查；这不等于已完成新增库真实服务器实测。实际连接、权限、驱动返回类型、取消及审计须在对应服务器上独立验收。

已支持对象树宽度与 SQL / 结果比例拖拽，方向键调整、双击 / Enter 复位；查询页签分别保留比例，窗口变小时自动约束尺寸。字段名称优先显示，完整元数据可悬停查看。

已补充只读结果网格（列宽、固定列、区域复制、本页筛选/排序、完整值查看）、当前语句/选区/全文执行、SQL 格式化、执行耗时与当前页内存历史；对象名称复制与插入、页签重命名/复制/批量关闭、侧栏折叠及布局偏好记忆。没有增加表格编辑、数据提交或事务控制。

第二轮只读优化：查询工具栏优先执行操作，连接与未观测事务详情收进弹层；结果页签支持横向滚动，SQL 来源按需展开；结果读取失败可独立重试，保留原执行和 SQL，不重新执行。网格补充类型标记、完整原值提示、只读右键菜单与清除筛选；结构页按名称、类型、注释筛选已加载字段，明确显示分页范围与原始序号。PostgreSQL 的 `?column?` 仅在展示层显示为“未命名列”，悬停保留真实名称。

第三轮补全与大字段优化：补全按当前 SELECT 子句、作用域和光标位置筛选，FROM / JOIN / 逗号处列出关系；别名点号仅返回其字段；JOIN 同名字段按来源分别显示并插入限定名，ON 条件不引用后续 JOIN 的表，USING 仅列两侧共有字段。支持 CTE、派生表、相关子查询、投影别名和 UNION 分支隔离；声明位置及字符串 / 注释不混入目录建议。请求绑定文档版本、光标和当前查询，切换页签后旧候选失效。长单行 SQL 格式化后重新显示光标位置，避免沿用旧横向滚动位置而呈现空白。补全弹窗以固定定位跨越编辑区 / 结果区分隔边界，避免底部候选被裁切。补全使用 HTTP，Alt + / 与右键“智能补全”可主动调用；Enter / Tab 都替换当前标识符。暂不根据外键生成整段 JOIN，也不推断函数返回字段或任意表达式输出类型。

结果表格以 240 字符短预览显示大字段，换行 / 制表符可见，原值与复制保留完整内容。双击或 Enter 打开独立只读 Monaco 查看器，支持查找、自动换行、全屏与 JSON 原文 / 格式化切换。二进制按数据库类型识别并显示十六进制、ASCII 和字节数；NULL 与空字符串明确区分。超过 128 Ki UTF-16 单位的值分段查看，查找范围为当前片段，复制完整值包含全部片段。JSON 格式化输入上限 128 Ki、输出上限 512 Ki，超过上限回退原文并提示；数字 token 原样保留，避免大整数精度损失。只读查看器不提供数据修改或提交。

当前语句范围通过 HTTP `POST /consoles/{id}/analysis` 获取，返回 UTF-16 范围；前端不自行按分号切割。MySQL / PG 使用 Go 后端原生解析器及连接 SQL mode；扩展方言通过有界 SELECT 扫描器识别词法边界，完整方言语法仍由数据库验证。扫描器不会证明函数无副作用，也不能替代数据库只读权限。分析失败时提示明确选区，不降级为执行全文。执行及未知提交期间分析失效，完成后重新获取范围。

以下仍是后续目标：索引与 DDL、可信事务状态及事务控制、错误行列定位、SQL 与对象定义跳转。当前结构页提供列、类型、可空与注释；事务状态明确显示未观测。

## 1. 目标与边界

工作区由对象导航树、工作页签、查询编辑区、执行结果区组成。对象树负责定位；查询页签负责 SQL 与连接上下文；对象页负责结构与明确触发的数据预览；执行及结果保留其产生时的上下文。

必须遵守以下规则：

1. 单击树节点只选中，箭头只展开或收起；二者都不改 SQL、不执行查询、不切换查询连接。
2. 双击表或视图默认打开**结构页**。读取业务数据必须明确点击“预览前 200 行”。
3. 顶部 `+` 继承当前查询或对象页的上下文；树菜单“在此新建查询”采用该节点上下文。创建后每个查询都有独立 console 与数据库连接。
4. V1 的 single 模式只显示当前 selector 配置、授权的数据库范围。数据库层用于表达上下文，不意味着可以枚举或连接服务器上的其他数据库。
5. 元数据使用 HTTP 按需读取；执行状态继续使用现有 SSE。此次不增加 WebSocket。
6. 断线仍可编辑 SQL；任何重连、事件恢复、切换页签都不得自动重放 SQL。
7. 草稿默认只在内存中保留。未经企业策略允许，不自动把 SQL 写入 localStorage、sessionStorage、IndexedDB、Electron 文件或其他浏览器磁盘存储。

## 3. 页面布局

- 左侧对象树：桌面默认宽 300px，可拖拽调整；顶部保留数据库范围说明、搜索与刷新。窄屏改为有标签的“对象”按钮和抽屉，不能只有隐藏侧栏。
- 右侧工作页签：查询页与对象页同层；图标区分类型，查询标题显示名称及未保存标记，连接或执行状态有文字 / 可访问标签。
- 查询页：执行工具栏 → Monaco → 可调整高度的结果 / 消息区域。数据库与 Schema 上下文紧邻执行按钮，始终可见。
- 对象页：对象完整路径 → “结构”及“数据预览”子页。默认结构；进入“数据预览”先显示说明与“预览前 200 行”按钮，不立即读数据。
- 页签少时使用理想宽度，`+` 紧跟最后一页；增多时均匀缩至最小宽度后水平滚动。遵循仓库现有主题、Nuxt UI、图标及 Web / Electron 兼容约定。

## 4. 对象树模型

### 4.1 PostgreSQL

```text
连接名称 · PostgreSQL
└─ 已配置数据库
   ├─ public
   │  ├─ 表
   │  │  └─ orders
   │  │     ├─ 列
   │  │     │  ├─ id : bigint
   │  │     │  └─ created_at : timestamp
   │  │     └─ 索引
   │  │        └─ orders_pkey
   │  └─ 视图
   └─ 其他已授权 Schema
```

### 4.2 MySQL

```text
连接名称 · MySQL
└─ 已配置数据库
   ├─ 表
   │  └─ orders
   │     ├─ 列
   │     └─ 索引
   └─ 视图
```

MySQL、MariaDB、ClickHouse、OceanBase MySQL 模式不重复显示一层与数据库同名的 Schema。PostgreSQL、Oracle、SQL Server、Db2、Dameng、OceanBase Oracle 模式保留 Schema 层；默认 Schema / search_path 来自服务端，不默认假设 `public`，也不把数据库名当成缺失的 Schema。V1 不承诺跨库切换。

对象类型、索引、DDL、注释等仅在服务端声明并实际返回该能力时出现。空目录显示“暂无对象”；能力不支持、无权限与请求失败必须分别表达，不能伪装成空目录。函数、存储过程等不因原型有占位就成为 V1 承诺。

节点采用服务端稳定标识及结构化路径，不用拼接 `schema.name` 充当唯一标识；正确支持包含点、引号、空格、Unicode 的名称。显示名、检索值与生成 SQL 时的方言引用分别处理。

### 4.3 交互语义

| 操作                               | 行为                                    | 不产生的副作用                             |
| ---------------------------------- | --------------------------------------- | ------------------------------------------ |
| 单击节点文字 / 图标                | 选中并显示完整路径                      | 不追加 SQL，不切换 console，不读取业务数据 |
| 点击展开箭头                       | 展开 / 收起该分支，首次展开按需取元数据 | 不执行 SQL 文档，不改变查询上下文          |
| 双击连接、数据库、Schema、类型目录 | 展开 / 收起                             | 不创建新查询                               |
| 双击表 / 视图                      | 打开该对象结构页；已打开则聚焦已有页    | 不读表行，不改变当前查询文档               |
| 双击列 / 索引                      | 打开所属对象结构页并定位对应字段 / 索引 | 不插入字段，不执行查询                     |
| 右键 / Shift+F10                   | 打开该节点菜单，菜单明确显示目标        | 不改变原查询连接或 SQL                     |

表 / 视图菜单按实际权限及能力提供“查看结构”“预览前 200 行”“在此新建查询”“生成 SELECT 到新查询”“复制限定名称”“刷新”。数据库 / Schema 菜单提供“在此新建查询”和“刷新”。V1 不放入未经完整设计的删除、重命名或直接修改数据动作。

“生成 SELECT”只生成新文档，绝不自动执行；标识符按当前方言正确转义，包括 SQL Server 方括号内的 `]]`、双引号及反引号转义，名称中的点不拆成路径。粘贴、复制、导出仍遵循现有 `can_paste` / `can_copy` / `can_download` 等策略，但元数据导航不能因禁止粘贴而整体禁用。服务端仍对每次元数据、SQL、预览请求独立授权。

### 4.4 搜索、分页与异常

- 目录按层延迟加载；节点加载独立，刷新当前节点不折叠整棵树。初始页建议 100 个节点，之后使用游标分页；不可一次拉取全库对象再渲染。
- 搜索覆盖**当前配置数据库内完整授权范围**，不只过滤已加载节点。输入去抖、取消过期请求，后返回的旧请求不能覆盖新搜索。
- 搜索结果保留数据库 / Schema / 类型路径；定位结果时展开必要祖先。清空搜索恢复此前展开状态与焦点，不影响查询页。
- 目录分页明确显示“加载更多”，搜索分页可继续读取；不得以“前 100 个匹配项”冒充完整搜索。大列表使用虚拟化且保留键盘焦点。
- 每个分支区分未加载、加载中、已加载、空、无权限、失败、缓存过期。失败只在该节点显示原因与重试；不得使查询 console 失效。
- 无搜索结果显示“当前数据库中无匹配对象”；没有对象显示“暂无对象”；连接断开保留已加载树并标注过期，禁用需要网络的动作。
- 元数据通过独立、有限额的 catalog 连接池读取，不借用正在执行 SQL 或处于事务中的查询连接。按授权身份、selector、数据库隔离，设置池上限、排队上限、超时和并发限制；不得因浏览目录返回查询连接的 `console_busy`。
- 目录连接不继承查询中的临时表、未提交 DDL 或会话变量。UI 说明其来自已提交的目录视图；补全仍结合目标查询自己的实际上下文。显式刷新后再更新结构，不把缓存当作实时事实。

## 5. 查询页签与上下文

每个查询页具有自己的文档 ID、Monaco model、SQL、版本、选区、光标、撤销栈、滚动位置、console ID、连接状态、事务状态和执行列表。切换页签只切换视图，不销毁 model 或重新连接。

上下文规则：

| 入口                             | 新查询上下文                                                           |
| -------------------------------- | ---------------------------------------------------------------------- |
| 查询页处于活动状态，点击顶部 `+` | 复制该查询的数据库及 Schema 默认上下文；新 console、新连接，不复制事务 |
| 对象页处于活动状态，点击顶部 `+` | 使用该对象所属数据库与 Schema，并在创建前显示目标                      |
| 树菜单“在此新建查询”             | 采用该节点数据库 / Schema；表、列、索引继承所属对象上下文              |
| 树菜单“生成 SELECT 到新查询”     | 同节点上下文，并填入生成 SQL；不执行                                   |

仅选中树节点不改变顶部 `+` 的继承来源。新页创建后展示服务端确认的上下文；失败保留文档及错误，允许用户显式重连。页面必须能区分“树中当前选中”与“这个 SQL 将在哪个连接执行”。

更换查询数据库 / Schema 应通过“以此上下文新建查询”完成，V1 不在原页悄悄替换 console。显式重连保留原 SQL 和结果；原连接的事务与临时会话状态不迁移。

### 5.1 编辑与执行

- 编辑与数据库连接生命周期分离；查询运行、断线、会话过期时仍能编辑文档，但权限策略造成的编辑限制继续生效。断线不能改变已有文档内容。
- 工具栏显示确切执行范围：“运行选中”“运行当前语句”“运行全部”。Ctrl / Cmd+Enter 执行选区；无选区时只在语句边界可可靠识别时执行当前语句。
- 语法未完成、解析不支持或范围不明确时，不静默退化成执行全文；提示选择 SQL 或明确点击“运行全部”。原型没有证明真实分句能力，实施时需要独立验证。
- 执行记录冻结 SQL 快照、文档版本、范围、console 及上下文。发送后编辑文档不会改变已经提交的执行，也不会使旧结果看起来属于新 SQL。
- 同一 console 同时只允许一个执行；其他查询页可独立运行。运行按钮随当前页状态变化，取消只作用于明确显示的执行。
- 使用既有 `request_id` 幂等提交契约。请求结果未知时保留原始 ID 与 SQL，只能恢复该次提交的状态；不能产生新的 ID 自动重发。会话失效或服务重启后不自动重放。
- 语义补全的目标始终是当前查询 console；目录树选中不改变补全目标。断线可保留本地关键字与标明过期的缓存建议，丢弃过期文档版本 / console 的异步补全回复。

### 5.2 结果、错误与审计

结果区始终绑定 `execution_id` 与 SQL 快照，显示执行时的数据库 / Schema、开始时间、耗时、返回 / 影响行数、截断及分页状态。多个语句结果使用结果区内的子页签，不能与上层查询页签混淆。

提交新执行时保留上次可用结果，标为“上次执行”；新执行有可展示结果后再更新。执行失败或未知不能伪造空结果或清掉已有结果。分页仅读取既有 result ID，不重新执行原 SQL；结果过期明确提示，需要用户主动再次运行。

SQL 错误放在所属执行的“消息”中，包含可用的错误码、位置与说明；目录错误留在树内，连接错误留在相应连接状态。重复列名按 ordinal 保留；BIGINT / DECIMAL 精度、NULL、Unicode 沿用现有传输及渲染约束。

SQL 执行状态与审计状态分别显示。`succeeded` 不代表审计成功；`audit_status=recorded` 表示本地持久化成功，在 managed 模式可能仍待同步 Core，在 single 模式为本地审计，不得统一标成“已上传”。审计失败不诱导用户重跑成功 SQL。

## 6. 对象结构与数据预览

结构页显示对象完整路径及元数据更新时间。按服务端能力分为列、索引、约束、DDL 等区域；列至少包含名称、原始类型、可空、默认值等实际可获信息。未知字段显示“未提供”，不猜测默认值、主键或表大小。

同一对象默认复用结构页；查询页始终独立。刷新结构只重新读取元数据，不替换查询，不自动刷新业务数据。复制名称、DDL、生成 SQL 等动作遵循企业复制 / 粘贴策略。

“预览前 200 行”必须显式点击，并显示目标对象与行数上限：

- 通过独立的受控预览 console / 连接执行，不能占用用户查询事务；按现有连接限额创建与释放。
- 请求经过正常授权、执行状态、取消和审计流程，不能用特殊未审计元数据接口读取业务数据。
- 显示实际预览 SQL 和结果来源；默认不承诺排序。“前 200 行”是最多 200 行，不承诺每次返回同一批。
- 首版为只读展示，不支持单元格写回。进入对象页、展开树、切换结构子页均不自动触发预览；再次读取必须主动刷新。

预览 SQL 使用方言对应的上限：SQL Server `TOP (200)`，Db2 `FETCH FIRST 200 ROWS ONLY`，Oracle / OceanBase Oracle 模式 `WHERE ROWNUM <= 200`，其余方言 `LIMIT 200`。默认查询在 Oracle / Dameng / OceanBase Oracle 模式使用 `DUAL`，Db2 使用 `SYSIBM.SYSDUMMY1`。这些生成规则有单元测试；适配服务器版本和模式的最终验证仍需实测。

大字段统一使用只读查看器。除 PG / MySQL 类型外，类型标记包含 Oracle CLOB / NCLOB / RAW / LONG RAW、SQL Server NVARCHAR(MAX) / IMAGE、Db2 DBCLOB，以及 ClickHouse Nullable / LowCardinality 包装和 Array / Map / Tuple。文本值以 `0x` 开头不自动视为二进制，必须同时匹配二进制类型及服务端约定编码。嵌套大整数要求后端以精确字符串传输，前端不对已经丢失精度的 JSON 数字进行猜测修复。

## 7. 连接、执行与事务状态

| 维度     | 状态                                          | 交互                                                                 |
| -------- | --------------------------------------------- | -------------------------------------------------------------------- |
| 查询连接 | connecting / ready / lost / closed            | 非 ready 禁止提交；文档仍保留；lost 显示“新建连接”，不自动重放       |
| 会话     | ready / locked / closed / expired             | 非 ready 禁止新连接及执行，保留编辑与已有结果；提示实际原因          |
| 执行     | queued / running / cancel_requested           | 对应执行标记处理中；仅允许一次取消请求，等待服务端确认               |
| 执行     | succeeded / failed / canceled / unknown       | 展示真实终态；unknown 明确说明结果未知，不能当成失败后自动重试       |
| 事务     | autocommit / idle / active / failed / unknown | 服务端权威状态；仅在实际支持时显示事务动作；unknown 不伪装成安全空闲 |

事务状态不可通过扫描 `BEGIN` / `COMMIT` 字符串推断，尤其不能把 MySQL 隐式提交和 PG 失败事务当作同一行为。需由后端报告实际自动提交设置、事务状态、能力与适用动作；不支持可靠观测时应诚实展示限制，并禁用依赖该判断的快捷操作。

**取消执行不等于回滚事务。** `cancel_requested` 不是终态；取消后由服务端确认 SQL 状态，再刷新事务状态。MySQL 语句可能在取消竞态中成功，PG 可能留下失败事务，UI 不根据点击了取消就显示已回滚。

取消按钮按服务端 `can_cancel` 能力显示可用性。显式为 `false` 时，禁用按钮及调用入口，并解释“此数据库驱动暂不支持取消正在运行的查询”；旧服务未返回字段时保留既有行为。不能取消的活动查询关闭时提示等待执行结束，不显示或承诺“取消后关闭”。当前 Db2 驱动通过此能力声明限制，前端不按数据库名称猜测。

关闭查询 / 工作区前统一处理：

1. 有未保留 SQL 时提供“返回编辑”“按策略允许的方式保留 / 导出”“丢弃并关闭”；内存草稿不能承诺在刷新或关闭浏览器后恢复。
2. 有执行进行中时提示具体任务；用户明确选择取消并关闭后等待取消及关闭结果，不把未知结果写成成功。
3. 有 active / failed 事务时显示目标及后果，默认返回；允许显式“回滚并关闭”，不提供默认或自动提交。
4. 事务或连接状态 unknown 时提示无法确认，保留 SQL、执行信息与核对线索；不能声称关闭已经证明所有变更回滚。
5. 浏览器强制退出不能保证异步完成；使用平台可用的离开提示，后端独立承担断线超时与资源清理。Electron 关闭防护通过现有适配层实现。

## 8. 草稿、防丢与恢复

- 默认每个文档只在内存维护，切换树、页签、结果、断线均不清除。关闭单页前做未保存检查；会话被锁定或服务器重启也不清除当前内存文档。
- “未保存”表示当前文档尚未按企业允许方式保留，不因成功执行 SQL 就清除标记。提示必须说明刷新 / 退出后内存草稿会消失。
- 企业策略可允许用户明确启用持久草稿或手动保存 / 导出；实施前定义保留期限、作用域、清理和敏感信息规则。默认不启用、不回退到磁盘，不把 token、密码、结果行写入草稿。
- `can_copy` / `can_download` 等限制继续适用，不能以“防丢”为由绕过。策略禁止导出时提供返回编辑及明确丢弃选择。
- SSE 中断保留编辑和当前结果；按既有 reset / 查询执行状态恢复，序列号去重，旧 console 事件不能覆盖新 console。恢复事件订阅不提交 SQL。
- 明确重连创建新 console；原事务、临时表及会话设置不可自动迁移，旧结果标记为原连接结果。

## 9. 键盘与可访问性

树使用标准 tree / treeitem 语义，报告层级、展开状态、选中与加载状态；焦点与选中分别维护。图标、颜色不能成为唯一状态提示。

| 键盘操作（树获得焦点时） | 行为                                                          |
| ------------------------ | ------------------------------------------------------------- |
| 上 / 下                  | 移到上 / 下一个可见节点                                       |
| 右                       | 展开；已展开时移到第一个子节点                                |
| 左                       | 收起；已收起时移到父节点                                      |
| Home / End               | 当前可见树的首 / 末节点                                       |
| Enter                    | 与双击一致：目录展开，表 / 视图打开结构                       |
| Space                    | 仅选中                                                        |
| Shift+F10                | 当前节点上下文菜单                                            |
| Escape                   | 关闭菜单 / 抽屉；搜索中按层次清除或退出并恢复焦点，不取消 SQL |

Ctrl / Cmd+F 在编辑器内查找 SQL，在树区域聚焦对象搜索。执行快捷键只在查询编辑器作用域生效；对象页、搜索框不能误执行 SQL。窄屏、键盘和触控均有显式“查看结构”“预览数据”入口，不依赖双击或右键。

## 10. 待补协议与实现边界

以下为**新增协议需求，尚非现有 API 承诺**。落地前与 Go 端统一字段及错误码，避免前端模拟成已支持：

| 能力               | 最小返回 / 约束                                                                                                  |
| ------------------ | ---------------------------------------------------------------------------------------------------------------- |
| 目录能力与范围     | 当前模式、允许数据库范围、默认上下文、可用对象类型、结构字段能力及事务观测能力；不泄漏范围外对象                 |
| 分层目录 HTTP      | 按 parent / node kind 读取子项；稳定 ID、结构化对象路径、children 能力、cursor / next_cursor；支持取消与有界读取 |
| 全范围搜索 HTTP    | 在当前授权数据库内按关键字与类型查找，返回路径和分页；后端执行授权过滤，不能靠客户端隐藏                         |
| 对象结构 HTTP      | 列、索引、约束、可选 DDL / 注释、更新时间及字段可用性；特殊名称与同名对象无歧义                                  |
| catalog 资源隔离   | 独立有界连接池、授权隔离、超时 / 限流错误；不使用活动查询 console，不暴露凭据                                    |
| console 与事务状态 | 服务端确认的上下文、连接状态、自动提交与事务状态；变更通过 SSE 及状态查询同步，重连 ID 有明确边界                |
| 显式事务动作       | 只对支持的 console 开放 commit / rollback；权限、并发与结果未知处理明确，必要审计不能省略                        |
| 执行 / 预览        | 沿用 request_id、execution、result、cancel 与审计链；预览上限由服务端约束，不能只在 UI 截断                      |

已有普通 HTTP 负责提交 / 取消 / 目录 / 结构 / 分页；SSE 只推送连接、执行等服务端状态变化。事件断线使用已有状态查询与 reset 恢复；没有需要双向持续实时通信的新需求，不引入 WebSocket。

## 11. 实施顺序与验收

### A. 优先完成对象树与查询联动

- [ ] PG / MySQL 按各自真实层级显示，V1 不枚举配置外数据库，不显示假能力。
- [ ] 单击、箭头、搜索、右键和刷新不会修改 SQL、创建查询执行或更换当前 console。
- [ ] 双击表 / 视图打开结构页，网络记录没有业务数据预览执行。
- [ ] “在此新建查询”使用节点上下文；顶部 `+` 使用当前查询上下文，即便树选中了另一 Schema / 对象。
- [ ] 目录与搜索按授权范围在服务端分页；首批之外的对象可搜索定位；重复名、点、引号、Unicode 名称正确。
- [ ] 查询运行期间仍能浏览元数据，不出现借用该 console 导致的 busy；目录失败不破坏运行查询。
- [ ] 空目录、无搜索结果、无权限、超时、断线与过期缓存有不同呈现，可独立重试；大树及 320px 视口可操作。

### B. 完成独立查询页、结构页与显式预览

- [ ] 两个查询的 SQL、撤销栈、上下文、console、事务、执行及结果互不覆盖；每个查询真实使用独立连接。
- [ ] 切页、连接失败、断线后可继续编辑，旧 SQL 与结果保留；无 SQL 自动重放。
- [ ] 已有结构页被复用；结构、列、索引 / DDL 仅展示实际能力。“生成 SELECT”开新页但没有执行请求。
- [ ] 预览必须显式点击，最多 200 行，权限与审计正常，独立连接不干扰查询事务；刷新结构不刷新数据。
- [ ] 一页、两页、缩小、溢出时页签与相邻 `+` 正确；小屏抽屉和完整键盘导航可用。

### C. 完成执行与防丢闭环后才可宣称可替代客户端

- [ ] 选区、当前语句、全文执行范围可见；不可靠分句不执行全文兜底；多语句结果与执行快照正确绑定。
- [ ] 新执行失败 / 未知时仍可核对上次结果；结果分页不重跑 SQL；审计失败不会提示重跑成功 SQL。
- [ ] 取消保持 cancel_requested 到真实终态；覆盖取消竞态成功、PG 失败事务及 MySQL 事务仍在的情况，不把取消当回滚。
- [ ] active / failed / unknown 事务的关闭保护经过真实数据库验证；从不自动提交，断线不谎报回滚成功。
- [ ] dirty 文档关闭、工作区退出与页面刷新有符合运行环境的提示；默认存储检查证明 SQL 未自动落盘。
- [ ] SSE 断线 / reset / 事件乱序、提交响应丢失、会话锁定 / 过期、服务器重启均不丢当前内存文档、不自动重放；结果未知保持可见。
- [ ] Web 与 Electron、复制 / 粘贴 / 下载权限、主题和可访问性检查通过；真实 MySQL / PG 测试与原型模拟的证据分别记录。
