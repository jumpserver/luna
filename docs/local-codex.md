# Luna 本地 Codex

Electron 桌面端可用本机 Codex 接管工作台助手和终端助手，继续使用原有 AI 面板。Web、文件、SQL 和脚本助手继续使用 Kael。此功能不注册 MCP 客户端、不新增 OAuth 授权。

## 使用

1. 安装 codex-cli 0.167.0 或更新版本，并在本机完成登录与模型服务配置。
2. 在客户端的“设置 → 通用 → 本地 Codex”中填写可执行文件（默认 `codex`），可选填写模型，检测安装后启用并保存。
3. 在原有工作台 AI 面板或终端 AI 面板中对话。工作台可以委派任务给当前终端，两个助手均使用本机 Codex。

修改配置会停止已有 AI 任务并重置对话。配置按站点和账户保存；模型凭据仍由 Codex CLI 管理。检测安装只验证版本，不代表已经登录或模型可用。

## 权责

Codex 负责模型推理与工具选择。Luna 采集当前工作台上下文，展示输出与审批，并将工具调用交给原有执行通道。Core、Koko、Chen 继续检查资产权限、命令 ACL、执行和操作审计。

工作台运行时关闭本机 shell、外部 MCP 服务器、插件、网页与计算机操作等通用工具，只注册当前工作台或终端声明的工具。模型不能通过本机 shell 直接连接资产。`auto` 自动放行普通只读工具；数据库元数据、写操作和破坏性操作仍需人工审批；`always` 每次审批，不提供跳过写操作审批的模式。连接器要求的风险确认与工单审批仍由连接器处理。

每个会话绑定原窗口、站点登录、组织和资源会话。切换后端、组织、账户、锁屏或退出会停止对应本地任务。原有浏览器与服务端助手不受本地进程退出影响。

本地对话不写入 Kael 的集中聊天历史；连接器的执行审计仍然保留。UI 历史仅在客户端运行期间保留，每段对话限制 4096 个事件与 4 MiB；Codex 自行管理模型上下文。同一登录最多 12 个本地对话、4 个活动任务，共用一个 app-server 进程。

## 协议与验证

使用 Codex app-server 的原生 stdio JSON-RPC、`dynamicTools` 和 `item/tool/call`。动态工具属于实验协议，因此检测最低版本，并对事件隔离、工具注册、审批、结果投递和取消进行回归验证。
