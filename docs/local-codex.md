# Luna 本地 AI

Electron 桌面端的“本地 AI”使用 Codex 引擎接管工作台助手和终端助手，继续使用原有 AI 面板。引擎运行在本机，模型可以使用云端或本地的 Responses API 服务。Web、文件、SQL 和脚本助手继续使用 Kael。

## 使用

1. 登录站点后打开独立的“设置 → 本地 AI”。默认选择客户端管理版本，点击“下载并安装”安装 Codex 0.167.2；也可选择已有的 codex-cli 0.167.0 或更新版本，填写可执行文件路径。
2. 填写 Base URL 和 API Key，或选择沿用本机 Codex 的配置与登录状态。两种方式均自动获取模型列表，可搜索选择、刷新或手动输入模型 ID；已有配置留空沿用默认模型。API 服务需提供兼容的 `/models` 接口才能自动获取。“检测安装”检查程序版本；“测试模型连接”使用无工作台工具的临时对话发送一条简短消息。配置完成后启用并保存。
3. 在原有工作台 AI 面板或终端 AI 面板中对话。工作台可以委派任务给当前终端，两个助手均使用本机 Codex。

修改配置会停止已有 AI 任务并重置对话。配置按站点和账户保存。API Key 使用操作系统凭据能力在本机加密保存，仅通过环境变量交给本地引擎；设置读取接口只返回密钥是否已保存。API 模式使用客户端独立的 Codex 配置目录，不修改本机 Codex 的全局配置。系统加密存储不可用时可沿用已有 Codex 配置。

引擎按操作系统和 CPU 架构从官方 `@openai/codex` npm 包下载，校验固定版本的 SHA-512，流式解压到客户端私有目录并检查版本后启用，无需安装 Node.js/npm。客户端管理版本不会自动更新；升级时应同步验证 app-server 协议兼容性。

## 权责

Codex 负责模型推理与工具选择。Luna 采集当前工作台上下文，展示输出与审批，并将工具调用交给原有执行通道。Core、Koko、Chen 继续检查资产权限、命令 ACL、执行和操作审计。

工作台运行时关闭本机 shell、外部 MCP 服务器、插件、网页与计算机操作等通用工具，只注册当前工作台或终端声明的工具。模型不能通过本机 shell 直接连接资产。`auto` 自动放行普通只读工具；数据库元数据、写操作和破坏性操作仍需人工审批；`always` 每次审批，不提供跳过写操作审批的模式。连接器要求的风险确认与工单审批仍由连接器处理。

每个会话绑定原窗口、站点登录、组织和资源会话。切换后端、组织、账户、锁屏或退出会停止对应本地任务。原有浏览器与服务端助手不受本地进程退出影响。

本地对话不写入 Kael 的集中聊天历史；连接器的执行审计仍然保留。UI 历史仅在客户端运行期间保留，每段对话限制 4096 个事件与 4 MiB；Codex 自行管理模型上下文。同一登录最多 12 个本地对话、4 个活动任务，共用一个 app-server 进程。

## 协议与验证

使用 Codex app-server 的原生 stdio JSON-RPC、`dynamicTools` 和 `item/tool/call`。动态工具属于实验协议，因此检测最低版本，并对事件隔离、工具注册、审批、结果投递和取消进行回归验证。
